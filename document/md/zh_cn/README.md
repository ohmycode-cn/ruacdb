# ruacdb（运行时统一访问控制器数据库）

## 前言

  RUACDB 是一个由 C/C++/Rust 实现的运行时统一访问控制的MINI数据库。其中大部分功能使用 C++ 编写。我不确定 RUACDB 未来会变成什么样，
但我希望探索一个更激进的数据库系统。这意味着 RUACDB 可能会在某些节点或特定版本阶段进行重大重构。RUACDB 的核心理念是绝对模块化。每个模
块只需要提供定义良好的接口，而无需了解其他模块的内部实现，从而确保长期的可维护性和可扩展性。我不是一名专业的软件工程师（也许将来会成为），
只是一个自由软件爱好者。如果你对 RUACDB 感兴趣，欢迎参与开发和讨论。

## 愿景

  RUACDB 受 Linux 哲学启发，秉承"小而专注"、"大而全"、"模块化"和"可扩展"的原则。
  RUACDB 采用多语言实现：大部分功能使用 C++ 实现，内存安全关键部分使用 Rust，性能关键部分使用 C。这种设计充分发挥了每种语言的优势，
在确保开发效率和安全性的同时实现最佳性能。
  RUACDB 在 C/C++ 代码中使用了 Rust 的用完即丢哲学，这种做法看起来不符合行业标准。但是，这使得 RUACDB 的代码更加安全、更加可维护，
在语言标准方面，RUACDB 将彻底摒弃过时的编程范式和语言标准。RUACDB 的最低 C++ 标准是 C++17，但实际项目使用 C++26，编译器标准也设置
为 C++26。对于 C 组件，RUACDB 将直接采用 C23 标准。Rust 组件将使用官方 Rust 标准库的最新长期支持版本。RUACDB 是一个复杂的项目，
可能会非常具有挑战性！总之 RUACDB 是一个追求新语言标准的项目，即使 C++26 还未正式在 ISO C++标准委员会发布。
  RUACDB 就像操作系统一样，RUACDB 有自己的标准库，这意味着第三方库将逐渐被自己的标准库取代。未来，RUACDB 将拥有自己的项目标准库，这
可能需要重新发明一些轮子，这既是挑战也是学习机会。
  RUACDB 有自己的数据库模型、内核层、用户层和网络层。类似于 Linux 用户系统，RUACDB 的用户层有自己的用户空间，默认的 root 用户拥有
全部权限并控制 RUACDB 系统。未来，RUACDB 还将引入用户+组权限模型。

## ruacdb 项目标准库

  RUACDB 的标准库 rstd 是一个严格隔离的库模块， rstd 的各个子模块之间明确禁止任何依赖关系，每个子模块只负责自己的功能并且提供明确接口。
